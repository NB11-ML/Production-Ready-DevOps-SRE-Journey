# Day 81: Introduction to Amazon EKS with Terraform

## 📝 Overview
Up until now, you have been running Kubernetes locally with KinD. That works great for learning, but the AI-BankApp needs a true production environment: a managed control plane, auto-scaling nodes, persistent EBS storage, and IAM integration.

Amazon EKS (Elastic Kubernetes Service) is AWS's managed Kubernetes offering. The AI-BankApp project already has a complete Terraform configuration that provisions a production-grade EKS cluster. Today, we will understand EKS architecture, study the Terraform configs, provision the cluster, and connect to it.

## 🛡️ Task 1: Understand EKS Architecture

### 1. What does "Managed Kubernetes" mean?
*   **AWS Manages the Control Plane:** AWS handles the API server, etcd (key-value store), scheduler, and controller manager. AWS ensures high availability across multiple Availability Zones (AZs) and handles patching/upgrades.
*   **You Manage the Data Plane:** You manage the worker nodes (EC2 instances) where your actual application Pods run.

### 2. Core EKS Components
*   **EKS Control Plane:** Managed by AWS, runs in an AWS-owned VPC, and is accessible via an API endpoint.
*   **Node Groups:** EC2 instances that run your Pods.
    *   *Managed Node Groups:* AWS handles provisioning, scaling, and updates.
    *   *Self-Managed Nodes:* You manage the EC2 Auto Scaling groups yourself.
    *   *Fargate Profiles:* Serverless compute, with no nodes to manage at all.
*   **VPC and Networking:** EKS runs inside your VPC with subnets distributed across AZs.
*   **IAM Integration:** EKS uses IAM roles for cluster access and Pod-level permissions using IRSA (IAM Roles for Service Accounts).

### 3. EKS Add-ons (used in AI-BankApp)
*   `coredns`: Internal DNS resolution inside the cluster.
*   `kube-proxy`: Network routing and load balancing for services.
*   `vpc-cni`: AWS VPC CNI plugin; assigns native AWS VPC IPs directly to Pods.
*   `eks-pod-identity-agent`: Enables Pod-level IAM roles.
*   `aws-ebs-csi-driver`: Allows Pods to dynamically provision and use AWS EBS volumes (critical for MySQL and Ollama storage).
*   `metrics-server`: Enables `kubectl top` commands and Horizontal Pod Autoscaling (HPA).

## 🛡️ Task 2: Study the AI-BankApp Terraform Configuration

Clone the repository and examine the `terraform/` directory:
```bash
git clone -b feat/gitops https://github.com/TrainWithShubham/AI-BankApp-DevOps.git
cd AI-BankApp-DevOps/terraform
ls

```

### File Breakdown:

* **`variables.tf` and `terraform.tfvars`:** Defines default variables (`aws_region = "us-west-2"`, `cluster_name = "bankapp-eks"`, `node_instance_type = "t3.medium"`).
* **`vpc.tf` (Networking):** Uses the `terraform-aws-modules/vpc/aws` module. Creates 3 AZs with Public subnets (for load balancers), Private subnets (for worker nodes), and Intra subnets (for control plane ENIs). Includes a NAT Gateway for outbound internet access.
* **`eks.tf` (Cluster):** Uses the `terraform-aws-modules/eks/aws` module. Provisions 3x `t3.medium` instances (min 3, max 5) using the AL2023 AMI. Installs all 6 EKS add-ons and configures IRSA for the EBS CSI driver.
* **`argocd.tf`:** Installs ArgoCD using the `argo-cd` Helm chart. Depends on the EKS module being ready.
* **`outputs.tf`:** Outputs the `aws eks update-kubeconfig` command and the ArgoCD initial password retrieval command.

## 🛡️ Task 3: Provision the EKS Cluster

*Ensure you have Terraform (>= 1.0), AWS CLI v2, kubectl, and Helm installed.*

**1. Configure AWS Credentials:**

```bash
aws configure
# Enter: Access Key ID, Secret Access Key, Region (us-west-2), Output (json)
aws sts get-caller-identity

```

**2. Initialize and Apply:**

```bash
cd terraform

terraform init
terraform plan
terraform apply

```

## 🛡️ Task 4: Connect to Your Cluster

**1. Update Kubeconfig:**

```bash
aws eks update-kubeconfig --name bankapp-eks --region us-west-2

```

**2. Verify the Connection:**

```bash
kubectl config current-context
kubectl cluster-info
kubectl get nodes -o wide

```

## 🛡️ Task 5: Deploy the AI-BankApp Manually

Before setting up GitOps, deploy the app manually to validate the cluster works.

**1. Apply the Raw Manifests:**

```bash
cd ../  # Back to the repo root

kubectl apply -f k8s/namespace.yml
kubectl apply -f k8s/pv.yml
kubectl apply -f k8s/pvc.yml
kubectl apply -f k8s/configmap.yml
kubectl apply -f k8s/secrets.yml

kubectl apply -f k8s/service.yml
kubectl apply -f k8s/ollama-deployment.yml
```

```bash
kubectl get pvc -n bankapp
kubectl get pv
kubectl get hpa -n bankapp
```


## 🛡️ Task 6: Understand EKS Costs and Clean Up Strategy

**Important: Do NOT leave the cluster running when you are not using it. EKS is not free.**

### Cost Breakdown

| Component | Cost (approximate) |
| --- | --- |
| **EKS Control Plane** | $0.10/hr (~$73/month) |
| **t3.medium nodes (3x)** | $0.042/hr each ($91/month total) |
| **NAT Gateway** | $0.045/hr + data transfer ($33/month) |
| **EBS volumes (15Gi total)** | ~$1.50/month |
| **LoadBalancer (ArgoCD)** | $0.025/hr ($18/month) |
| **Total for this lab** | **$220/month ($7/day)** |

### Clean Up (Keep Cluster for Days 82-83)

Delete the BankApp workloads to save node resources:

```bash
kubectl delete -f k8s/hpa.yml
kubectl delete -f k8s/bankapp-deployment.yml
kubectl delete -f k8s/ollama-deployment.yml
kubectl delete -f k8s/mysql-deployment.yml
kubectl delete -f k8s/service.yml
kubectl delete -f k8s/secrets.yml
kubectl delete -f k8s/configmap.yml
kubectl delete -f k8s/pvc.yml
kubectl delete -f k8s/pv.yml
kubectl delete -f k8s/namespace.yml

```

### Complete Destruction (End of Day 83 or taking a break)

```bash
cd terraform
terraform destroy

```
