# 🧩 Day 65 Cheat Sheet: Terraform Modules

### Terraform Modules File Structure

A standard, production-ready module architecture separates the orchestrator from reusable components.

```text
terraform-modules/
├── main.tf                    # Root module: Calls child modules and registry modules
├── variables.tf               # Root module: Accepts inputs for the environment
├── outputs.tf                 # Root module: Prints final values to the console
├── providers.tf               # Root module: Defines AWS provider and versions
└── modules/
    ├── ec2-instance/          # Custom Child Module 1
    │   ├── main.tf            
    │   ├── variables.tf       
    │   └── outputs.tf         
    └── security-group/        # Custom Child Module 2
        ├── main.tf            
        ├── variables.tf       
        └── outputs.tf         

```

### Module Syntax & Usage

**1. Calling a Local Child Module**
Use a relative path in the `source` argument to reference a custom module stored in your repository.

```hcl
module "web_server" {
  source             = "./modules/ec2-instance"
  ami_id             = "ami-1234567890"
  instance_type      = "t3.small"
  subnet_id          = module.vpc.public_subnets[0]
  instance_name      = "terraweek-web"
}

```

**2. Calling a Public Registry Module**
Use the `//` format for the `source` argument. Always pin the version.

```hcl
module "vpc" {
  source  = "terraform-aws-modules/vpc/aws"
  version = "~> 5.0"
  
  name = "terraweek-vpc"
  cidr = "10.0.0.0/16"
}

```

**3. Referencing Module Outputs**
To use a value generated by one module inside another, use the `module..` syntax.

```hcl
# Accessing the VPC ID generated by the registry module
vpc_id = module.vpc.vpc_id

# Accessing the Security Group ID generated by the custom sg module
security_group_ids = [module.web_sg.sg_id]

```

### Dynamic Blocks

Dynamic blocks allow you to iterate over complex variables (like lists or maps) to generate nested configuration blocks inside a resource, eliminating repetitive code.

```hcl
variable "ingress_ports" {
  type    = list(number)
  default = [22, 80, 443]
}

resource "aws_security_group" "this" {
  name   = "dynamic-sg"
  vpc_id = var.vpc_id

  dynamic "ingress" {
    for_each = var.ingress_ports
    content {
      from_port   = ingress.value
      to_port     = ingress.value
      protocol    = "tcp"
      cidr_blocks = ["0.0.0.0/0"]
    }
  }
}

```

### Essential Module CLI Commands

* **`terraform init`**: Initializes the working directory, downloads registry modules into `.terraform/modules/`, and creates local symlinks for custom child modules.
* **`terraform init -upgrade`**: Bypasses the lock file and cached versions to download the newest available module and provider releases that satisfy your configuration's version constraints.
* **`terraform get`**: Downloads and installs modules referenced in the configuration without performing a full backend or provider initialization.
* **`terraform validate`**: Checks the syntax, structure, and internal consistency of your configurations, ensuring all required module variables are passed correctly.
* **`terraform state list`**: Lists all tracked resources, displaying module resources with their hierarchical prefixes (e.g., `module.vpc.aws_vpc.this[0]`).
