# 🛡️ Day 53 Cheat Sheet: Kubernetes Services & Networking

Kubernetes Services provide static network identities and load balancing for ephemeral Pods across your infrastructure. 

## 📦 Core Service Types

| Service Type | Primary Use Case | SRE Context |
| :--- | :--- | :--- |
| **ClusterIP** | Backend microservices, databases | The default. Strictly internal IP. Highly secure, preventing unauthorized external access. |
| **NodePort** | Local testing, non-cloud bare metal | Opens a static port (30000-32767) on all physical Worker Nodes. |
| **LoadBalancer** | Production public-facing apps | Provisions a physical external load balancer via a cloud provider (e.g., AWS NLB). |

## 💻 Critical Networking Commands

* `kubectl get svc -n dev` - List all active services, their types, and assigned static ClusterIPs.
* `kubectl get endpoints <service-name> -n dev` - Verify the Service is successfully routing to active Pod IPs. An empty list indicates a label selector mismatch.
* `kubectl port-forward svc/<service-name> 8080:80 -n dev` - Securely tunnel into a service from your local machine for browser testing.
* `kubectl expose deployment <name> --port=80 --target-port=80` - Imperatively generate a basic service quickly without YAML.

## 🛠️ Stable DNS Testing Workflow

To avoid terminal race conditions and kernel architecture crashes (`Exit Code 139` Segmentation Faults), always use updated base images and background the pod before executing an interactive shell.

```bash
# 1. Launch a stable background pod
kubectl run net-test --image=busybox:latest --restart=Never -n dev -- sleep 3600

# 2. Exec into the running shell
kubectl exec -it net-test -n dev -- sh

# 3. Test short-name routing (Same namespace communication)
wget -qO- http://app-clusterip

# 4. Test FQDN routing (Cross-namespace communication)
nslookup app-clusterip.dev.svc.cluster.local

```

## 🚨 Common Troubleshooting Signatures

* **Empty Endpoints (`<none>`):** The `selector` tag in the Service YAML (e.g., `app: nginx`) does not exactly match the Pod `labels` generated by the Deployment.
* **`<pending>` EXTERNAL-IP:** Expected behavior for a `LoadBalancer` Service deployed on a local virtualization cluster (like `kind` or Minikube) because there is no cloud controller attached to provision physical hardware.
* **`NXDOMAIN` Noise:** CoreDNS is functioning normally but printing its built-in domain search attempts (e.g., `.cluster.local`) before finding a match. Querying the full Fully Qualified Domain Name (FQDN) bypasses this noise.
