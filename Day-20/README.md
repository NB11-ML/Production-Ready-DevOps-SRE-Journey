---

## 🎯 Project Features

This project mimics a daily task for a System Administrator or SRE. The script includes the following production-ready features:

*   **Input Validation:** Ensures a valid file path is provided before execution, preventing silent failures.
*   **Metrics Extraction:** Uses `grep` to count total error and failure occurrences dynamically.
*   **Critical Event Formatting:** Isolates "CRITICAL" log entries and formats them neatly with exact line numbers using `sed`.
*   **Data Aggregation (Top 5):** Leverages a powerful `awk` and `sort` pipeline to identify the top 5 most frequently occurring error messages.
*   **Automated Reporting:** Groups all processed data and outputs a clean, timestamped text report (e.g., `log_report_2026-08-11.txt`).
*   **Log Archiving:** Automatically moves the analyzed log file into an `archive/` directory to keep the working space clean.

---

## ⚡ Execution & Usage

**1. Make the script executable:**
```bash
chmod +x log_analyzer.sh

```

**2. Run the script against a log file:**

```bash
./log_analyzer.sh sample_log.log

```

**3. View the generated report:**

```bash
cat log_report_$(date +%Y-%m-%d).txt

```

## 💡 Professional Takeaways

* **Data Pipelines:** Chaining commands together (`grep | awk | sort | uniq | head`) is the most efficient way to process large datasets in Linux without writing complex loops.
* **Stream Editing:** Using `awk` to strip unnecessary columns (like timestamps) is crucial for grouping and counting identical error messages.
* **I/O Redirection:** Wrapping multiple `echo` commands inside curly braces `{ ... } > file.txt` is cleaner and significantly faster than opening and closing the file for every single line of output.
